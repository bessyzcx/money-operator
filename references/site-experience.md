# Optional visual report
This reference applies only when HTML or hosting is available and useful. The core workflow completes with ledger plus text/Markdown insights; lack of hosting is not a blocker.

## Delivery choices
Use a local self-contained HTML file when supported. Host only when the user authorizes a destination and access level and the current environment has the required tools. Platform-specific website skills may be used if available; never require another AI to have them installed. Reuse an existing approved project when appropriate. Return a URL only after actual deployment success; if hosting fails, deliver the local/text report and disclose that failure.

## Privacy
Keep website source in a separate dedicated directory, never the financial workspace root. Include only reviewed derived and masked data needed for the report. Do not copy raw statements, screenshots, credentials, full ledgers, personal profiles or local paths into it. Inspect the exact publishing file list. An unlisted URL is not private access; verify the access model before claiming privacy. If only public access is available, use a local report unless the user explicitly approves public publication.

## Review and report
Review state: scope, coverage, remaining count, stable question IDs, evidence, suggested answers, copyable reply. Apply replies to the ledger first and regenerate remaining questions. Browser-local drafts are not authoritative ledger decisions.

Report state: selected dates/event and actual coverage, main finding, gross/refund/net reconciliation, spending drivers, event versus recurring costs, fixed versus adjustable commitments, and up to three actions. Add optional dated financial snapshots only with sufficient evidence. Apply period-scope.md before showing monthly figures.

Use clear type, accessible contrast, direct labels, readable tables and mobile layouts. Essential conclusions must not depend on hovering. Every chart must add useful evidence. Mask identifiers and keep social previews free of private amounts and findings.

## Validation
Reconcile all values to the ledger. Check filters, links, empty states, question counts and currency labels. Keep old/estimated/missing facts visibly distinct. For generated sites run the supported build and verify the deployed version if publishing; for standalone HTML inspect the document and disclose any unavailable visual checks. Missing site tooling never blocks a text report.
